# Editorial, delivery and operations evidence

This inventory describes repository-owned behavior at adoption. A runbook establishes an operator procedure. Live credentials, vendor configuration, uptime and recovery rehearsals require independent operational evidence.

| Capability | What to inspect | Acceptance evidence |
| --- | --- | --- |
| Public content | Fixture and Sanity perspectives, queries, crops and references in `src/lib/content.ts`. Public Studio schema in `sanity/schemaTypes/index.ts` and Studio configuration in `sanity.config.ts`. Private course authoring uses the separate learning schema and media permissions. | `scripts/validate-content.ts`, `scripts/validate-sanity-query.mjs`, `tests/catalog-fallback.test.ts`. Inspect both draft handlers for authenticated entry, same-origin return and POST exit. |
| Editorial migration | Webflow and selected source media are migration inputs. Inspect `MIGRATION.md`, `scripts/normalize-source.mjs` and `scripts/migrate-sanity.ts` for the dry run, explicit write option, stable identifiers and existing editor content. | Run `pnpm content:validate` on local records. A baseline review never needs a CMS upload or access to private submissions. The migration notes describe several offers at their original import date. |
| Public and private previews | The Pages builder substitutes synthetic or unavailable UI for live routes, filters server code and qualifies asset URLs for the review base path. The separately served staging social gallery uses only public artwork. | `scripts/build-pages.mjs`, `scripts/pages/prepare-layout.mjs`, `scripts/validate-pages.mjs`, `tests/review-layout.test.ts`, `docs/STAGING_SOCIAL_GALLERY.md`. |
| Reusable local rehearsal | The sandbox prepares its own application copy, state, identities, media, booking bridge and synthetic checkout. Its local test-login and RPC facilities belong to the sandbox. | `scripts/sandbox/start.mjs`, `scripts/sandbox/services.mjs`, `scripts/sandbox/verify-course-flow.mjs`, `tests/sandbox.test.ts`, `docs/LEARNING_SANDBOX.md`. |
| Deployment and recovery | Separate build inputs, runtimes, database projects, payment modes and transactional delivery for each environment. Install/activate and smoke-check before guarded retention. Root deployment documentation owns operator commands. | `docs/HOSTING.md`, `docs/CANDIDATE_BUILDS.md`, `docs/STAGING_ISOLATION.md`, `deploy/test_staging_isolation.py`, `deploy/test_prune_releases.py`, `tests/health.test.ts`. `docs/BACKUPS.md` describes independent backups, retention after success and restoration verification. |
| Scheduled work and persistence | The protected platform cron and the two environment-specific systemd timers deliver queued notifications. Database migration files run in order with transaction-level locking and version recording. The ledger and quiz migration scripts have their own reconciliation and compatibility requirements. | `vercel.json`, `deploy/deliver-email.mjs`, `scripts/database-migrate.ts`, `scripts/migrate-ledger.ts`, `scripts/migrate-quiz-completion.ts`, and `docs/QUIZ_COMPLETION_ROLLOUT.md`. A checked-in scheduler declaration documents a supported configuration, not a second confirmed live scheduler. |
| Media workflows | Source photographs, WebP renditions, image crops, fonts and the wide/square social cards follow the owning design and source attribution. The social review generator creates a local proof sheet. | `docs/IMAGE_QUALITY.md`, `docs/SOCIAL_PREVIEWS.md`, `tests/prepared-photos.test.ts`, `scripts/social-images/generate.ts`. The `prophoto-seeing` and `prophoto-workflow` video projects own their preparation scripts, compositions, preview/check/render commands and scoped HyperFrames guidance. |

The coverage checker enumerates current Next entry files, configured cron paths, application and film package commands, schema entry modules, SQL migrations, job/service definitions, repository scripts, film compositions and CI workflows. External integrations without a dedicated route are mapped in the platform evidence index. Adding a new entry-point convention also requires extending discovery and its regression tests.
